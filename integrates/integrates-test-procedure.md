# 整合测试流程（aliwepaystat）

## 目标
- 验证 CSV 导入 → SQLite 持久化 → 从数据库读取构建统计 → 生成 HTML 报表的整合流程正确性。

## 前置条件
- 已安装 Go 环境。
- 依赖已拉取：`go mod tidy`。

## 测试数据
- 采用微信账单 CSV（UTF-8 编码），包含表头与至少一条交易记录。
- 单条交易示例：
  - `交易时间`: `2024-09-15 10:00:00`
  - `交易类型`: `支付`
  - `交易对方`: `商家A`
  - `商品`: `餐饮-测试`
  - `收/支`: `支出`
  - `金额(元)`: `20.00`
  - `支付方式`: `零钱`
  - `当前状态`: `支付成功`
  - `交易单号`: `wx-001`
  - `商户单号`: `m-001`
  - `备注`: `无`

## 测试步骤
1. 创建临时测试目录（使用 Go `t.TempDir()`）。
2. 在目录根创建测试用微信账单 CSV 文件，内容包含表头与示例数据行。
3. 启动整合流程：
   - 初始化 SQLite 数据库（`OpenDB` + `EnsureSchema`）。
   - 加载已存在交易 `id`（`LoadExistingIDs`）。
   - 导入 CSV 到数据库（`ImportCsvToDB`）。
   - 从数据库构建统计（`BuildStatsFromDB`）。
   - 生成报表（`GenHtmlStat`，输出到 `stat/`）。
4. 校验输出：
   - `stat/aliwepaystat-index.html` 存在且非空。
   - `stat/aliwepaystat-202409.html` 存在且包含 `202409 收支统计报告` 字样。
   - 数据库存在月份 `202409`（`QueryYearMonths`）。

## 运行方法
- 在项目根执行：
  - `go test ./integrates -v`
  - 或 `go test ./... -v`。

## 预期结果
- 测试通过，说明导入、去重、统计与报表生成链路工作正常。
- 若失败，检查：
  - CSV 表头是否与解析器常量完全匹配；
  - 编码是否正确（微信为 UTF-8；支付宝为 GBK）；
  - `list.min.amount` 可能影响明细展示（需金额大于阈值）。
